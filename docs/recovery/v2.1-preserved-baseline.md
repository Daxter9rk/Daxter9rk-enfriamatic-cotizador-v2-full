# Enfriamatic V2.1 — Baseline preservado

Fecha: 2026-08-13

## Identificación

- Rama: `refactor/v2.2-modular-recovery`
- Commit del baseline preservado: `5d4e281b1500393486e0a0ef4bc09f79a1ae346c`
- Tag: `v2.1-preserved-before-mvp-restructure`
- Commit de imágenes privadas: `78a8ef8`
- Commit de retiro del CRUD técnico: `5d4e281`

Este baseline conserva el working tree auditado de Enfriamatic V2.1 antes de iniciar la migración arquitectónica modular y la reducción del MVP. No se descartaron cambios locales ni se alteró la historia existente.

## Resumen funcional

El baseline conserva el flujo operativo actual, incluyendo cotizaciones, solicitudes, documentos PDF, autenticación, autorización, auditoría y catálogo comercial. También consolida el flujo de imágenes privadas del catálogo mediante Functions Gen 2, validación real de bytes, Storage administrado por backend, idempotencia, compensación y cleanup pendiente.

El CRUD técnico de catálogos internos se retiró de la UI operativa. La colección y sus reglas permanecen disponibles para usos internos existentes.

## Conjuntos incluidos

1. Flujo completo de imágenes privadas del catálogo comercial: Functions, repositorio, validación, workflow, cliente frontend, Rules, auditoría, seed y pruebas.
2. Retiro del CRUD técnico de `CatalogsPage` de la navegación y del routing operativo.

Los seis archivos que estaban no trackeados en la auditoría quedaron versionados en el primer commit. Las dos eliminaciones de `CatalogsPage` quedaron registradas en el segundo commit.

## Validaciones ejecutadas

- Frontend: lint, typecheck, tests (23 suites, 50 tests), build y format check.
- Functions: lint, typecheck, tests (9 suites, 30 tests) y build.
- Firestore Rules: 25 tests mediante Emulator Suite.
- Storage Rules: 9 tests mediante Emulator Suite.
- Validación integral oficial `npm run validate:emulators`: PASÓ, incluyendo build, Rules y E2E con Auth, Firestore, Storage, Functions y Hosting emulados.

El comando aislado `npm run test:e2e` fue ejecutado sin emuladores y quedó bloqueado por entorno (`127.0.0.1:5000` no disponible). La suite E2E sí quedó validada dentro de `validate:emulators`.

## Limitaciones conocidas

- La validación se realizó exclusivamente contra la Emulator Suite demo.
- Esta preservación no constituye un despliegue ni una validación contra Firebase real.
- Los artefactos de build y reportes ignorados no forman parte del baseline versionado.

## Arquitectura objetivo posterior

La evolución posterior será incremental hacia un monolito modular, Clean Architecture ligera, Firebase serverless y eventos sólo cuando sean necesarios. Este documento no autoriza ni contiene esa migración.

## Alcance MVP posterior

Después de preservar este baseline se evaluará retirar del MVP visible:

- Instalaciones;
- Equipos;
- Solicitudes;
- Actividad;
- Catálogos internos.

Auditoría interna podrá conservarse aunque se retire la pantalla Actividad. El Catálogo comercial se evaluará por separado. Ayuda y soporte tendrá inicialmente un adaptador simulado para generación y envío de tickets. No deben borrarse datos históricos durante la reducción inicial.

## Regla de despliegue

Esta versión preservada no debe desplegarse automáticamente. Cualquier despliegue posterior requiere una decisión explícita y una validación independiente del estado que se pretenda publicar.
